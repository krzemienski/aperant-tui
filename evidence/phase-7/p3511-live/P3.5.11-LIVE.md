### Defect found: silent agent-type fallback mislabels graph nodes

`observability.ts:369` —
`const resolvedAgentType = (rawAgentType in AGENT_CONFIGS ? rawAgentType : 'spec_gatherer') as AgentType;`
— silently coerces any subagent type string not present in `AGENT_CONFIGS`
to the label `spec_gatherer`, with no visible indication in the UI that a
fallback occurred.

**Confirmed: `complexity_assessor` is not a key in `AGENT_CONFIGS`.**
Exhaustive grep of `apps/desktop/src/main/ai/config/agent-configs.ts`
finds zero occurrences of the string `complexity_assessor` anywhere in
that file — only `spec_gatherer` and the other 30 real `AgentType` union
members are keys. `subagent-executor.ts:44`'s `resolveAgentType()`
deliberately maps `complexity_assessor` → `'spec_gatherer'` *for tool-set
purposes* (its own comment: `// Uses spec_gatherer tools + complexity
assessor prompt` — a legitimate design choice, since `complexity_assessor`
needs a minimal read-only tool set and reuses `spec_gatherer`'s). But
`SpawnSubagentInputSchema`'s `agent_type` enum
(`spawn-subagent.ts:24-38`) still allows an orchestrator to pass the raw
string `"complexity_assessor"` to the tool, and that raw string — not the
resolved `AgentType` — is what flows into the `SUBAGENT_*` task-event's
`agentType` field (`worker.ts`'s new code posts `params.agentType` from
the tool call, before `resolveAgentType()` ever runs inside
`subagent-executor.ts`). `observability.ts:369`'s independent fallback
then coerces this raw `"complexity_assessor"` string to the *display*
label `spec_gatherer` for the same reason — but with no distinguishing
marker, so a viewer cannot tell a real `spec_gatherer` spawn from a
`complexity_assessor` spawn wearing that label.

**Effect on this run's captured evidence.** The saved trace artifacts
(`full-stream.txt`, `full-stream-2.txt`) contain exactly one *legible*
`SUBAGENT_SPAWNING` payload — for `spec_discovery` (a real `AGENT_CONFIGS`
key, rendered correctly, no fallback involved). The two nodes labeled
`spec_gatherer` in the graph screenshots were never independently
confirmed by a captured payload before this run's evidence directory was
cleaned up (see the correction below) — given the swarm-view row observed
mid-run read `complexity_assessor` (not `spec_gatherer`) for the first
spawn, the most parsimonious explanation is that at least one, plausibly
both, of the two `spec_gatherer`-labeled nodes are actually
`complexity_assessor` spawns wearing the fallback label. **The graph can
display a node type that never actually ran** — this is a real defect in
the code this session wrote, not present before this patch (it did not
exist prior to `SUBAGENT_*` handling because no code path constructed
child snapshots at all). It does not invalidate the topology proof
(`parentId`/tree-nesting are correct regardless of the type label), but
it does mean the specific claim "three distinct correctly-typed agent
kinds" in the original evidence-artifacts caption below was wrong and has
been corrected.
